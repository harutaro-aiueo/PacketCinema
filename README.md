# PacketCinema

**見えない通信を、映画のように。**

PacketCinemaは、ネットワークの仕組みをパケットの動きと解説で学ぶWeb教材です。コマンドを入力したとき、機器の間で何が起きているのか。接続の始まりから終わりまでを一つのストーリーとして再生し、「誰が、誰に、何を伝え、なぜ次へ進むのか」を一場面ずつ追いかけます。

## コンセプト

プロトコルの用語や静止した通信図だけでは、やり取りの順序と意味をつなげにくい。PacketCinemaは、その間にある「流れ」を見えるようにします。

- **まずは眺めて、全体をつかむ。** ピクセルアートの機器と、その間を移動するメッセージで通信を連続再生します。
- **気になった場面で止める。** 一時停止やステップ移動で、自分のペースで見直せます。
- **動きと理由を一緒に読む。** 図の中の短い解説から、技術情報や出典を載せた詳細へ進めます。

ネットワークを学び始めた人の最初の理解にも、学んだ知識を通信の流れとして整理し直すときにも使える教材を目指しています。

## 学べる通信

現在は次の3つの教材を公開しています。起動するとSSHの教材が開き、画面上部の「教材を探す」から名前や用途で検索して切り替えられます。

| 教材 | 追いかけるストーリー | アプリ内URL |
| --- | --- | --- |
| SSH | TCP接続、鍵交換、ホスト鍵確認、公開鍵認証、対話シェル、コマンド実行、切断 | `#/ssh` |
| TCP | SYN → SYN/ACK → ACKの3ウェイハンドシェイクによる接続確立 | `#/tcp` |
| STP | 3台のスイッチのBPDU交換、ルート選出、ポート状態の遷移、リンク断後の再収束 | `#/stp` |

SSHでは、`ssh learner@server` の入力から `whoami` の結果を受け取り、`exit` で端末へ戻るまでをたどります。STPでは、ループを防ぐために経路がどう選ばれ、障害時にどう切り替わるのかを16ステップで見ていきます。

## 見る・止める・深掘りする

1. **再生を見る。** メッセージの移動と端末内の処理が順番に進みます。
2. **場面を止める。** 通信図のクリック、または操作部以外にフォーカスがあるときのSpaceキーで一時停止・再開できます。
3. **見たい場面へ移動する。** 「戻る」「次へ」や左右キーでステップを移動し、「もう一度」で現在の場面を再生します。「最初から」「最後へ」、段階ボタンでも移動できます。
4. **理由を確かめる。** 「詳しい解説」で全文・技術情報・出典を確認できます。詳細や教材検索を開いている間は再生が止まります。
5. **全体を振り返る。** ページ下部の「フロー全体」を開くと、全ステップと通信方向を一覧でき、選んだ場面へ移動できます。

`#/ssh?step=12` のように、表示位置をURLで共有できます。ステップ番号は0始まりです。PCとスマートフォンに対応し、2台の機器の通信は画面の向きに合わせて左右・上下に配置します。

## ローカルで動かす

Node.jsとnpmが必要です。CIではNode.js 22を使用しています。

```sh
npm ci
npm run dev
```

表示されたローカルURLをブラウザーで開いてください。

本番用のビルドとプレビュー:

```sh
npm run build
npm run preview
```

## 教材としての表現範囲

PacketCinemaは、理解のために通信を整理したアニメーション教材です。実際のSSH接続やパケット取得は行いません。アニメーションの時間は説明のための演出で、実際の通信時間・処理時間を表すものではありません。

- **SSH:** 公開鍵認証に成功する代表例です。描画する単位は論理メッセージで、TCPセグメントと一対一ではありません。鍵交換用・ホスト認証用・ユーザー認証用の鍵を区別し、初回ホスト鍵確認では信頼できる別経路の指紋と照合します。入力文字や端末表示はまとめ、拡張交渉、認証方式探索、再鍵交換、再送、ウィンドウ調整、失敗系などは省略しています。処理の順序は実装により異なります。
- **TCP:** 単独教材は接続確立を扱います。SSH教材では、接続に加えてFIN・ACKの交換とTIME-WAITを含む切断の一例も示します。
- **STP:** 従来のIEEE 802.1Dを扱います。Listening／Learning／Forwardingと再収束の待機時間は短縮しています。

各場面の詳細には、出典や省略事項を記載しています。モデルの前提と実際の実装の違いを確かめながら学べます。

## 開発と教材の追加

React・TypeScript・Viteで構成し、教材データと共通プレーヤーを分離しています。

| 場所 | 役割 |
| --- | --- |
| `src/protocols/` | SSH・TCP・STPの教材と再利用する通信部品 |
| `src/domain/lesson/` | プロトコル・シナリオ・ステップの型と検証 |
| `src/player/` | 共通の再生処理、操作、詳細表示 |
| `src/visualization/` | 機器の配置、通信、端末内の演出 |
| `src/app/` | 教材の公開登録、URL解決、画面の組み立て |
| `src/styles/` | 共通テーマとスタイルの読み込み |
| `tests/contracts/`・`tests/e2e/` | 教材・依存境界の検証とブラウザー回帰テスト |

教材を追加する際は、[プロトコル追加手順](docs/adding-protocol.md)と[設計と依存ルール](docs/architecture.md)を参照してください。

検証コマンド:

```sh
npm test
npm run build
npm run test:e2e
```

E2EテストにはPlaywrightのChromiumを使います。未導入の場合は `npx playwright install chromium` を実行してください。
