# PacketCinema 日次実行プロンプト

以下をCodexのプロジェクト指定の定期タスクに保存する。プロジェクトは`PacketCinema`、実行時刻は日本時間の毎日06:00、各回は独立した実行とする。

```text
PacketCinema（harutaro-aiueo/PacketCinema）の日次改善を1回実行してください。まずリポジトリのAGENTS.md、docs/daily-automation.md、docs/git-workflow.mdを読み、全ての上限と停止条件を守ってください。docs/daily-automation.mdがmainにまだ無い場合は、設定PRのマージ待ちとして何も変更せず報告してください。

GitHubの最新mainとPR/Issue/CIを確認してください。既存の作業ツリーには触れず、最新mainから隔離したworktreeとcodex/daily-<日付>-<内容>ブランチを使ってください。GitHubに接続できない、mainを更新できない、worktreeを隔離できない、週内の自動PR数を確かめられない場合は実装を見送ってください。

日本時間の今日に自動PRが既に1件ある、今週に作成されたcodex/daily-ブランチのPRが3件以上、または未完了の自動PRが1件以上なら新しい実装をしないでください。閉じたPRも数えてください。候補は最新のPR用CI、未完了Issue最大3件、関連テストとTODOから1件だけ選びます。安全な低リスク候補がなければ変更なしと報告してください。

1テーマ、最大5ファイル、追加・削除合計概ね300行以内で、既存仕様を守る小さな改善だけを行ってください。教材の技術内容、共通プレーヤー、URL、依存関係、CI、Pages、権限に関わる変更や判断に迷うものは実装せず提案してください。検証失敗の修正は同じ原因について1回までです。

関連テストを実行し、コードを変えたらnpm testとnpm run buildを実行してください。文書だけならリンクと内容を確認してください。検証に失敗した場合や秘密情報・無関係な差分が疑われる場合は送信しないでください。成功時は送信範囲を確認し、作業ブランチにコミット・pushしてmain向けPRを1件作ってください。タイトルに[daily]を付け、目的、変更、検証、未確認事項を本文に記してください。mainへの直接push、force push、マージ、Pages公開、リリース、保護設定変更は行わないでください。

最後にPRのURLまたは見送り理由、実施した検証、残る人の判断を簡潔に報告してください。既存の作業をstash・reset・上書きしないでください。
```
