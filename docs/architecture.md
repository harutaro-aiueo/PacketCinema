# 教材とプレーヤーの構造

単一のReact/Viteアプリとして管理します。教材の追加単位はプロトコル、その中の再生単位はシナリオです。既存の表現で扱える教材は専用ディレクトリと公開登録の追加だけで増やせます。

## 責務

| 場所                 | 責務                                                   |
| -------------------- | ------------------------------------------------------ |
| src/domain/lesson    | Reactやブラウザに依存しない型・教材検証・方向ラベル    |
| `src/protocols/<id>` | シナリオ、通信部品、教材固有の文言とテスト             |
| src/player           | 再生時間、停止・再開、操作部、段階一覧、詳細、全体一覧 |
| src/visualization    | ノード配置、パケット移動、ローカル処理の演出           |
| src/app              | 公開登録、URL解決、各機能の接続                        |
| src/styles           | 共通テーマとCSSの読み込み順                            |
| tests/contracts      | 全教材の契約、依存境界、移行前の内容保持               |
| tests/e2e            | ブラウザ操作・縦横画面・拡張教材の回帰確認             |
| tests/fixtures       | 公開しないテスト専用教材・ブラウザ起動ページ           |

スタイルはapp/app.css、player/player.css、visualization/scene.cssに所有層ごとに置きます。共通画像はpublic/pixelsに置きます。

## 依存ルール

- domainはdomainだけに依存します。
- protocolsはdomainと自分の内部ファイルに依存します。他プロトコルの再利用はindex.tsの公開窓口に限定し、循環依存を禁止します。
- playerとvisualizationはそれぞれ自分の層とdomainだけに依存します。具体的な教材や登録一覧を参照しません。
- appがすべてを接続します。catalog.tsで教材全体を検証し、公開対象だけをURL解決と検索付き教材一覧に渡します。
- 共通層にプロトコル名や教材のステップIDによる分岐を追加しません。
- 検証はtests/contracts/dependencies.test.tsで行います。依存追加で失敗したら、ルールを緩める前に責務の置き場所を見直します。

## データと演出

ProtocolDefinitionは全シナリオと既定シナリオIDを持ちます。公開するシナリオIDはapp/catalog.tsで別に指定します。未公開のSSH単一コマンド実行とパスワード認証も構成・検証されますが、直接URLから表示できません。

Scenarioは見出し、バッジ、ノード、前提教材、注意事項、順序付きステップを持ちます。ステップIDはシナリオ内で一意です。

Stepはkindでmessageとlocalを区別します。messageはfrom/to、localはnodeとeffectを持ちます。ノードIDは任意の文字列で、状態もノードIDをキーに保持します。wireは技術情報の原文、displayWireは必要なときだけ指定する短縮表示です。

ローカル演出はtyping・stages・resultの3種類です。入力文字や処理段階の説明は教材データに持たせます。再生時間は通信6秒、ローカル処理3.2秒です。通信は5秒で到着し、残り1秒後に次へ進みます。詳細を開いている間は同じ再生時計が止まります。

TCPのcreateConnection/createDisconnectionはノード対応、段階名、ID接頭辞を受け取り、独立したコピーを返します。SSH側で公開窓口から組み込みます。

## URL互換性

- #/ssh?step=Nと#/tcp?step=Nは既定シナリオを表示します。番号は0始まりです。
- 非既定シナリオは#/protocol?scenario=id&step=Nです。移動後もscenarioを保持します。
- 空や不明なプロトコルはSSH、不明または未公開のシナリオはそのプロトコルの既定へ戻します。
- 不正な番号は0、上限超過は最後のステップに補正します。
- 旧auth/detailパラメーターは受け流します。これらは移行前の画面でも動作に反映されていませんでした。
- 手動・自動のステップ移動にはreplaceStateを使い、プロトコル切り替えには通常のハッシュリンクを使います。

## 複数ノードの境界

教材モデルと検証は3ノード以上を扱えます。現在の描画はnodesの先頭・2番目を画面上の2位置に配置します。CSSのclient/serverは配置用の既存クラスで、ノードIDではありません。

`topology.kind: "triangle"` を持つ3ノード教材は、`visualization/Topology.tsx` で描画します。3本のリンク上をメッセージが移動し、ステップの `linkStates` と `states` からリンクとノードの状態を表示します。通常の2ノード教材は既存の配置を使い、それ以外の構成は公開時に拒否します。描画の分岐は教材名に依存しません。

同時通信、実行時の分岐、実パケット取得、外部プラグイン、シナリオ選択UIは今回の対象外です。

## 移行の検証

移行前に採取したtests/fixtures/baseline.jsonには、公開SSH40ステップ、TCP3ステップ、未公開SSH2方式のID列と内容ハッシュがあります。migration.test.tsで旧形式に正規化して本文・技術情報も比較します。将来の教材改訂では差分をレビューした上で基準を意図的に更新してください。

npm test、npm run build、npm run test:e2eで確認します。既存のPagesワークフローも同じコマンドを使用します。
