# PacketCinema レビュー

コードパスはリポジトリルート基準。依頼された教材・差分と観点に絞る。
「技術的に正しいか」は技術面、「表示・操作」は画面・再生を確認し、総合レビューでは両方を扱う。
レビューのみならファイルを変更しない。敵対的レビューを明示された場合、利用可能な`adversarial-review`スキルと併用し、ここでは教材固有の観点を補う。

## 技術面

- 対象シナリオの前提・バージョン・省略事項を読み、通信順序、送受信方向、フィールド、状態遷移を一次資料と照合する。
- 出典URLがあるだけで正しいと判定しない。その節が該当ステップの説明を裏付けるか確認する。特に共有部品の組み込み後、接続・認証・切断の境界で対応を確認する。
- 応答を返す条件、任意処理、実装依存の挙動を無条件の必須動作として説明していないか確認する。例：SSHの要求に対する成功応答と`want reply`の対応。
- 論理メッセージと実際のパケット分割、演出時間とプロトコルのタイマーを区別する。
- 記載済みの簡略化は、その前提でも誤解を生む場合に指摘する。一次資料を確認できない事項は未確認として残す。

## 画面・再生

- `tests/e2e/`の関連テストを使い、変更した配置・動作をブラウザーで確認する。
- 新教材・配置変更では狭い縦画面、横画面、PCを確認する。STPの既存例は`tests/e2e/stp.spec.ts`。CSS境界を変更した場合は境界の両側を確認する（過去の再現例：667×480／481）。
- SVG内の文字はCSS指定値だけでなく表示倍率を考慮し、読める大きさか確認する。長い解説、状態ラベル、操作部の重なり・切れ・横スクロールを見る。
- 再生・停止・再開、ステップ移動、詳細や教材一覧を開閉したときの再生状態を確認する。タイマーに依存するE2Eは既存の時計制御や状態待機を参考にする。
- 途中ステップのURLを直接開く場合と再読み込みで、表示状態が通常の再生到達時と一致するか確認する。

## 報告

確認できた問題を優先度順に、対象ファイル・ステップ、条件、影響、根拠、修正方針とともに簡潔に示す。
推測を確定した不具合として扱わない。問題がない場合も確認範囲を示す。
静的照合、テスト、実画面での確認を区別し、未検証のブラウザーや範囲を明記する。
