# PacketCinemaの日本語を平易にする

PacketCinemaの学習者向け日本語を、初学者が通信の流れと理由を追える表現に整える。対象にはステップの説明、教材の前提・注意書き、見出し、画面内の案内文を含む。コード識別子、プロトコル上の名称、wire表示そのものは、学習者向け説明として書かれていない限り書き換えない。

## 基本方針

日本プレインランゲージ協会の[プレインジャパニーズ 9のガイドライン](https://japl9.org/plainjapanese/j10rules-analysis/)を参考にする。文面を短くすることより、学習者が正しい通信の順序・理由・条件を理解できることを優先する。

- 読み手を、プロトコルの専門用語にまだ慣れていない学習者として想定する。文脈から分かる情報は繰り返さず、必要な前提や用語は説明する。
- その文やステップで最も伝えたいことを先に置き、その後に理由や条件を説明する。通信の時系列や因果関係が主題なら、それらが自然に追える順序を保つ。
- 1文に詰め込む情報を減らし、長い文は分ける。50文字以内は目安として意識するが、技術用語や条件を削って機械的に合わせない。
- 日常的で具体的な語を選ぶ。専門用語が必要なら、初出で短く意味を補う。標準上の名称やメッセージ名は正確さのために残し、平易な言い換えだけで置き換えない。
- 回りくどい表現を避け、誰が何をするかを明確にする。できる範囲で能動態にし、主語と述語を近づける。実際の動作主体が重要な受動表現は、主体を誤らせる書き換えをしない。
- 二重否定や不要な否定を避け、肯定形で行動や状態を示す。ただし「応答しない」「必須ではない」など、否定そのものがプロトコル上の意味を持つ場合は維持し、何が否定されているか明確にする。
- 一覧や複数条件は、文章に詰め込まず箇条書きなどで整理する。画面内の短い文は、前後の見出しやステップとのつながりも含めて読みやすくする。

## 推敲時に守る技術的な意味

書き換え前後で、次の情報が保たれているか確認する。

- 送信者・受信者、メッセージの方向、処理の順序、状態の変化。
- 動作が起きる条件、応答を返す条件、任意か必須か、失敗時の挙動。
- プロトコル仕様で定まることと、実装依存のこと、教材で省略したことの区別。
- 論理メッセージと実際のパケット分割、アニメーション上の時間と実測時間の区別。

曖昧な原文を、根拠なく断定的な説明に変えない。意味を保ったまま平易にできない場合は、技術的な確認が必要な箇所として示す。技術レビューを依頼されていない場合、文章を整えるために教材全体の技術レビューへ範囲を広げない。

## 進め方

1. 対象文と前後のステップ、教材の前提を読み、読み手が知りたいことと文の役割を捉える。
2. 主な結論、主体と動作、理由、条件を分け、意味を変えない範囲で語順や文の長さを整える。
3. 修正文を前後の流れに戻して読み、用語の説明、因果関係、否定の対象が明確か確認する。
4. 文章レビューのみの依頼ではファイルを変更せず、問題箇所と修正案を示す。編集依頼では必要な範囲だけ変更する。

## 書き換え例

- 「サーバーからの応答を受信した後に、クライアントは接続を確立するために必要となる状態への遷移を行います。」
  →「クライアントはサーバーの応答を受け取ります。その後、接続に必要な状態へ移ります。」
- 「この要求への応答は必須ではありません。」
  →「この要求への応答は任意です。」

例は文体の目安であり、元の技術的意味と教材の前後関係に合わせて調整する。
